# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A semantic description of X-ray Absorption Spectroscopy (XAS) community standards (XDI, NeXus `NXxas`) using the Cross-Domain Interoperability Framework (CDIF). It is mostly **data artifacts** (SKOS vocabularies, SSSOM crosswalks, JSON Schema/frame/SHACL for the `xasDocument/1.0` profile, example XDI and JSON-LD), plus a few stdlib-only Python scripts that build and validate them. `README.md` is detailed and authoritative; read the relevant section before changing anything structural.

Work happens on branch `cdifxasRelease1.1` (not yet tagged; `main` is far behind). `origin` fetches from `CDIF-4-XAS/XAS-CDIF` and pushes to both that repo and the `smrgeoinfo/XAS-CDIF` fork.

## Commands

Scripts use only the standard library, except `release/FrameAndValidate.py` (needs `pyld`, `jsonschema`). There is no test suite or linter; validation is done by the build scripts themselves.

```bash
# Crosswalks: validate + regenerate crosswalk/*.tsv (fetches NXDL from GitHub at a pinned SHA)
python crosswalk/build_crosswalk.py
python crosswalk/build_crosswalk.py --check          # validate only, write nothing
python crosswalk/build_crosswalk.py --no-rml-check   # when no cdif-xas checkout sits beside this repo
python crosswalk/build_placement.py                  # cdifxas-placement.tsv, from ../cdifnexmetadata emit.py

# Glossary site (what CI runs; output to build/docs/, which is gitignored)
python tools/generate_glossary_html.py
python tools/generate_concept_files.py [--dry-run]

# Value-list vocabularies from NeXus NXDL enumerations
python tools/import_nexus_enumerations.py [--dry-run]

# Frame + validate one CDIF-XAS JSON-LD document against the release profile
python release/FrameAndValidate.py exampleMetadata/valid.jsonld -v

# Check a vocabulary against the CDIF concept-scheme profile (sibling checkouts)
python ../profile-conceptscheme/FrameAndValidate.py XAS_Glossary_SKOS.json -v \
    --schema ../metadataBuildingBlocks/_sources/profiles/cdifProfile/cdifConceptScheme/resolvedSchema.json
```

## Architecture: what is source, what is generated

The glossary is a concept hub; XDI and NeXus are two bindings to it.

```
XDI token  --\
              >-- CDIF XAS concept (XAS_Glossary_SKOS.json) --> CDIF JSON-LD
NeXus path --/
```

- **`XAS_Glossary_SKOS.json`** — master glossary, edited directly (the old xlsx is archived and unread). Every crosswalk subject must resolve here. Its filename is unversioned on purpose; CI publishes it as `XAS_Glossary_SKOS_v2.json` because per-concept files link to that name. `release/XAS_Glossary_SKOS_v2.json` is the released snapshot; `archive/XAS_Glossary_SKOS.json` is the superseded v1 with the same filename — don't confuse them.
- **`XAS_{edges,emissionlines,detectionmodes}_SKOS.json`** — value-list schemes generated by `tools/import_nexus_enumerations.py`, kept separate from the glossary deliberately (~478 values vs ~100 properties).
- **`crosswalk/*.tsv`** — all generated; `crosswalk/README.md` describes each. `cdifxas-placement.tsv` (concept → place in CDIF JSON-LD) is derived by `build_placement.py` from `CONCEPT_SLOTS` in `cdifnexmetadata`'s `emit.py`; change it there. The rest are **output** of `build_crosswalk.py`. Mappings are curated in Python tables inside that script; editing a TSV directly gets overwritten. The script validates each row against the glossary, the live NXDL, and the XDI keys read by the RML mapping in a sibling `cdif-xas-UKDS/` (or `cdif-xas/`, or `$CDIF_XAS_RML`) checkout. The TSVs are master copies that `cdifnexmetadata` duplicates under `src/cdifnexmetadata/data/`.
- **NeXus is pinned**: `PINNED_REF` in both `crosswalk/build_crosswalk.py` and `tools/import_nexus_enumerations.py`. Bumping it is a vocabulary change; regenerate and read the diff.
- **`release/`** — the `xasDocument/1.0` profile (resolved schema, frame, SHACL, implementation guide). Generated from `metadataBuildingBlocks/_sources/profiles/cdifCompositeProfile/xasDocument/`; edit there, not here.
- **`release/FrameAndValidate.py`** is a synced copy — header says DO NOT EDIT. The normative source is `CDIF/validation/tools/FrameAndValidate.py`, synced with `python tools/sync_frameandvalidate.py --apply` in that repo.
- **`exampleMetadata/`** — output of an external pipeline (`smrgeoinfo/cdif-xas` fork, checked out locally as `../cdif-xas-UKDS`) run over `exampleData/*.xdi`. Nothing in this repo generates it; regenerate there rather than hand-editing. Regenerating from upstream `UKDSResearch/cdif-xas` instead of the fork produces different, worse documents.
- **`archive/`** — superseded material and the published 1.0 deliverable; nothing reads it.

## Conventions that are easy to break

- Vocabulary `@context` declares **prefixes only**, no alias terms (`prefLabel`, `hasTopConcept`): the validator compacts with the document's own context, so aliases expand correctly but fail validation. Each vocabulary is **rooted on its scheme** with concepts inline under `skos:hasTopConcept`, not as `@graph` siblings, and declares `dcterms:conformsTo https://w3id.org/cdif/conceptscheme/1.1` in a `schema:subjectOf` catalog record.
- Emission-line primes become underscores in URIs (`Kb2'` → `kb2_`, `Kb2''` → `kb2__`) — see `slug()` in `tools/import_nexus_enumerations.py`. Stripping them would collapse distinct concepts onto one URI.
- `foaf:focus` NeXusOntology PURLs on the glossary don't resolve; `build_crosswalk.py` deliberately mints `nxdl:` IRIs under CDIF w3id instead (rationale in its `CURIE_MAP` comment). Prefer `seeAlso` to the NeXus manual.
- Physical mappings: `cdif:TextMapping` (`cdif:index` 1-based column, `cdi:minimumLength`/`cdi:maximumLength` including leading padding) for text columns; `cdif:LocatorMapping` (`cdif:locator`) for paths into NeXus containers. Widths are measured per file.
- Publishing: `.github/workflows/build-docs.yml` regenerates `build/docs` and deploys to `gh-pages`, guarded to run only in `CDIF-4-XAS/XAS-CDIF`. w3id (`perma-id/w3id.org` `ids/cdif/.htaccess`, `XAS_PAGES`) resolves `w3id.org/cdif/xas/*` there. If publication ever moves, follow the order in the workflow comment: enable Pages, confirm it serves, repoint w3id, then change the guard.
